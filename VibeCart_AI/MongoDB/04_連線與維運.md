# Flask 連線、權限與維運

狀態：Atlas DB 已建置與驗證；Flask 原程式未切換、未完成 schema v2 改寫。

## 憑證與使用方式

本目錄 `.env` 是 vibecart_app 的實際應用連線；`.env.schema` 是 vibecart_schema_manager 的維護連線。兩個檔案均由 Windows ACL 限制為本機目前使用者，並受 .gitignore 排除。不要將兩檔內容加入 Git、Markdown、聊天室或例外紀錄。主機與帳號資訊見 [Cluster 文件](01_Cluster設定與狀態.md)。

Flask 執行时使用 readWrite 應用帳號，維護帳號不供網站使用。`readWrite` 是 MongoDB 內建資料庫角色，不代表 Flask 的 admin/customer 授權；會員權限必須由 Service 層驗證。

既有程式在 `MuscleCore分析資料/website`，它的 .env 保持原值。本次建置不會自動讓舊 schema 程式相容新 DB。確認程式遷移後，以安全方式載入新連線：

```python
from pathlib import Path
from dotenv import dotenv_values
from pymongo import MongoClient

config = dotenv_values(Path('C:/LLM/LLM_PJ/VibeCart_AI/MongoDB/.env'))
client = MongoClient(config['MONGO_URI'], serverSelectionTimeoutMS=10000,
                     maxPoolSize=10, tz_aware=True)
database = client[config['MONGO_DB']]
database.command('ping')
```

每個程序共用 MongoClient，不在每個 HTTP request 建立；程序結束時 close。採 TLS，不關閉憑證驗證。保留現有 `MONGO_URI`／`MONGO_DB` 名稱；ENABLE_CHECKOUT=false。雲端正式秘密應存 Secret Manager，Cloud Run 網路與密鑰部署尚未執行。

## Schema 重建與驗證

在專案根目錄 `C:/LLM/LLM_PJ` 執行：

```powershell
& '.\MuscleCore分析資料\website\.venv\Scripts\python.exe' 'VibeCart_AI\MongoDB\bootstrap_schema.py'
& '.\MuscleCore分析資料\website\.venv\Scripts\python.exe' 'VibeCart_AI\MongoDB\verify_cluster.py'
```

本次使用現有 PyMongo 4.14.1、python-dotenv 環境。bootstrap 僅允許核實過的 host／DB，首次要求空資料庫，後續依 checksum、succeeded 紀錄及實際設定驗證；不清除資料、不覆蓋既有 validator 或刪除索引。若 checksum 改變或先前執行失敗，會停下要求檢查，不能直接改寫紀錄假裝成功。後續變更另建遷移版本。

驗證腳本將測試寫入放在回滾交易內，不保留測試會員、訂單或假向量。未執行真正舊資料迁移，未種入假商品或管理員。

## Validator 範圍與服務層責任

13 個集合已設 strict/error，限定 schema_version=2、欄位型別、必填、enum、陣列長度、日期及 Decimal128，拒絕未定義的頂層欄位。JSON Schema 不自動產生預設值；應用程式要明確寫入 nullable 欄位為 null。新資料採 local 登入；Firebase、歷史缺失商品及未知 AI 關聯不納入此空環境初始化，舊資料需先遷移再寫入。

DB 額外驗證商品特價／金額精度、訂單總額與明細計算、商品陣列去重、已付訂單 paid_at、主要事件必要關聯、512 維有限非零向量、推薦 rank 連續及 BGE score 範圍、報表日期範圍、摘要 BSON 大小與 AI 終態一致性。全部定義見 [實際 Schema](05_實際Schema與索引.md)。

以下仍由應用服務實作及驗收：有效外鍵與商品上下架、密碼雜湊演算法與登入、角色／所有權、白名單摘要語意與個資移除、URL 核准、Prompt／model revision 真實性、向量 hash／版本／L2 正規化一致性、推薦點擊對應、配額原子預扣、冪等 request_hash 與 HTTP 409。DB 約束不能替代這些流程。

## TTL、配額與資料保留

只有 ai_insights.expires_at 與 request_limits.expires_at 使用 expireAfterSeconds=0。設定已讀回，但未等待背景 TTL 刪除週期。讀取仍需比較 expires_at；ai_usage 不可 TTL 或重設配額；user_events 與 ai_requests 保留至專題驗收後決定保留期。

## 交易及網站驗收界線

21 項 DB 檢查通過，包含多集合交易回滾、條件扣庫存及唯一性。不等於 Flask 兩人搶庫存、付款流程、網路不明 commit 重送或完整 API 冪等測試已通過。正式啟用 Demo 結帳前仍需驗證相應程式，保持 ENABLE_CHECKOUT=false。

## 備份與恢復

Free 無 Atlas 雲端備份。本次新 DB 僅初始化紀錄，尚未執行備份還原演練。開始匯入舊資料前，停寫或建立一致性備份窗口，以 mongodump 匯出業務 DB；保留版本、筆數、金額總和、校驗值與 UTC 時間，存於受保護的專案外位置。mongorestore 先還原到測試副本比對，不能覆蓋正式資料。Free 不採依賴 oplog 的 PITR；僅回退網站不能回退 DB。
