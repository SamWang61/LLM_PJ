## 二、作品製作方向

本作品以既有運動商品購物網站為基礎，改以 **Python Flask** 重整系統架構，並加入「消費者個人化推薦」與「管理者營運洞察」兩項 AI 應用。目標不是只做一個能展示商品的網站，而是呈現 AI 如何分別協助消費者做購買決策，以及協助管理者理解商品與銷售資料。

系統規劃為兩個核心模組：

1. **VibeCart 消費者端**：依會員偏好、商品資料與操作紀錄，提供商品搜尋、推薦、購物車及模擬結帳。
2. **VibeInsight 管理端**：提供商品維護、銷售 KPI、推薦分析及雲端 LLM 營運洞察。

### 製作重點

- 將舊有購物網站改寫為模組化 Flask 網站。
- 使用 MongoDB Atlas 儲存會員、商品、偏好、訂單及 AI 分析紀錄。
- 導入本地向量模型，建立中文商品語意搜尋與推薦功能。
- 串接雲端大型語言模型 API，產出後台營運摘要與建議。
- 比較本地端 AI 與雲端 AI 在成本、速度、隱私及輸出品質上的差異。
- 完成可由外部瀏覽器操作的展示版本，並保留測試、部署及操作紀錄。

## 三、AI 應用與雙模型設計

本專題採取「**雲端 API 主系統＋低成本本地模型概念驗證（PoC）**」策略，在小組無額外硬體投資的前提下控制開發風險。預計開發比重約為雲端與網站整合 90%、本地模型 PoC 10%。

| 類別 | 模型／服務 | 專題用途 | 目前狀態 |
|---|---|---|---|
| Local AI | `BAAI/bge-small-zh-v1.5` | 中文商品文字向量化、語意搜尋及相似商品推薦 | 架構與流程已確認；下載、向量建立及實測待完成 |
| Cloud AI | Claude API | 彙整商品、訂單與 KPI，產生管理端營運洞察 | 串接規格已完成；實際模型 ID、額度及付費呼叫待驗證 |
| 本地生成式模型 PoC | `Qwen2.5-1.5B-Instruct`（規劃） | 與雲端 LLM 進行同題輸出比較 | 屬延伸驗證項目，尚未完成 |

> 說明：BGE 是語意嵌入模型，主要負責檢索與推薦，並非生成式 LLM。若要呈現老師要求的「本地生成模型與雲端模型同題比較」，將以 Qwen 小型模型進行 PoC，避免模型角色混淆。

## 四、系統與技術架構

| 層級 | 採用技術 | 用途 |

| 前端介面 | Jinja2、HTML、CSS、JavaScript | 購物前台與管理後台操作畫面 |

| AI 洞察 | Claude API | 管理端營運資料摘要與建議生成 |
| 網站部署 | Firebase Hosting＋Cloud Run | 靜態入口與 Python Flask 後端服務 |
| 版本管理 | GitHub | 程式碼、文件、分支及版本控管 |

## 十、目前風險與因應方式

| 風險 | 可能影響 | 因應方式 |
|---|---|---|
| 四週開發期較短 | 功能過多造成整合延誤 | 優先完成登入、商品、推薦、後台洞察及外網展示等 MVP |
| Cloud Run／Firebase 逾時或設定錯誤 | 網站無法穩定展示 | 保留 DEBUG 訊息、健康檢查、記錄檔與分段 API 測試 |
| 本地模型受限於硬體 | 推論速度較慢 | 本地端只做小型 PoC，主系統以 API 與預先計算向量為主 |
| Claude 額度或模型設定未確認 | 後台洞察無法呼叫 | 儘早完成金鑰與實際模型 ID 驗證，並保留測試資料與錯誤提示 |
| 組員分工尚未定案 | 工作重疊或遺漏 | 以 GitHub Issue、分支、里程碑及交叉驗收明確管理 |
