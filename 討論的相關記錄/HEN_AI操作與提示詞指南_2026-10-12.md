# HEN：如何用 AI 完成會員／購物工作

依據：`整體進度表_2026-10-12_1900.md`。本指南教操作與交付方法，沒有把下列待辦改成已完成。適用於能聊天、讀文件或操作程式碼的 AI；實際能力以該次對話可用工具為準。

## 一、先知道自己要交什麼

| 工作 | HEN 要完成的內容 | 先讀／先確認 | 交給誰 |
|---|---|---|---|
| R02／進度表 03 | 登入、停用、撤權、庫存、checkout 接口契約 | 現有程式＋SAM 資料契約，列出已確認與待確認 | SAM、JEFF |
| R08／進度表 18 | 註冊、登入、登出、active／role、舊 session 撤權 | auth.py 與會員測試；保留既有實作 | SAM 驗收；JEFF 接後台權限 |
| R08／進度表 19 | SKU 購物車、checkout 重送、庫存與錯誤處理 | store_v4.py、sku_gateway.py 與底層交易服務 | SAM 驗收；JEFF 接訂單操作 |
| 協作／進度表 28 | 搜尋／瀏覽／加購／購買事件觸發接口 | 既有事件寫入與 synthetic 隔離契約 | JEFF 核對消費者、SAM 遠端驗證 |
| 協作／進度表 30～31 | 可驗證的撤權與購物接口、操作步驟 | 角色／停用／重送／庫存邊界 | SAM 建少量私有帳號及整合驗收 |

HEN 沿用已有 Flask／v4 SKU 購物車服務。AI／管理後台由 JEFF 負責，資料庫 migration、私有測試帳號與部署由 SAM 負責。現階段 checkout 是示範流程；付款／退款契約未確認時，不能讓 AI 以改資料欄位宣稱完成真實付款。

## 二、在各 AI 系統如何提供文件

先看「能否讀檔、改檔、執行指令」，再選操作方法。品牌名稱不能保證這次對話有那些能力。

| 使用情境（例） | 文件怎麼給 | 指令怎麼下 | 你如何核對 |
|---|---|---|---|
| 一般聊天介面，例如 ChatGPT、Claude、Gemini 的聊天模式 | 上傳文件或貼相關全文；未連線的本機路徑只是文字，AI 不能憑路徑讀檔 | 用下面「讀文件」提示詞；要求引用檔名、章節及短摘錄 | AI 是否真的引用內容；缺附件時是否明說 |
| 有儲存庫連線的 AI 對話 | 指定 repo、分支、檔案；先要求回報能否讀到 | 加上目標 branch／commit；區分能讀與能寫 | 回報實際讀取的分支、SHA、檔案；沒有權限時改上傳 |
| 本機程式代理，例如 Codex、Claude Code 或具代理模式的 IDE | 開啟真正的專案根目錄，讓代理先檢查工作目錄、分支、異動與 AGENTS.md | 用下面的分段實作提示詞；要求實際改檔、執行測試 | 查看 diff、測試指令、exit code、commit／PR；不要只看文字答覆 |
| IDE 對話只附上部分檔案 | 明確附上契約、相關路由、服務、測試與模板；請 AI 列出看不到的部分 | 要求缺上下文先定位來源，不自行重建服務 | 確認附件足以追到呼叫鏈與交易層 |
| 換另一個 AI／新對話 | 提供本指南、最新交接摘要及這次變更 diff | 用「接續工作」提示詞 | 新 AI 先復述已完成／待完成，再接續剩餘工作 |

同一時間只讓一個 AI 修改同一工作目錄。另一個 AI 可以讀文件或審查貼上的 diff；要同時實作，先明確分配不同 worktree 與檔案範圍。

### 文件應按這個順序讀

| 次序 | 文件 | 讀取目的 |
|---|---|---|
| 1 | `docs/CURRENT_CONTEXT.md` | 知道現有資料與不可重匯的基線；它的日期較舊，責任／動態狀態以最新資料為準 |
| 2 | `專題進度/整體進度表_2026-10-12_1900.md` | 找 R02、R08，以及 28／30／31 的相依；分清程式、推送、部署、驗收 |
| 3 | `docs/HEN_AUTH_ORDER.md` | 讀全文，尤其末尾 10/7 更新，避免照最前面舊邀請／待分配狀態操作 |
| 4 | `docs/SAM_DATA_CONTRACT_2026-10-07.md` 中登入／D5／D4 相關節 | 這是提案，不能當作所有接口已實作或已接受；先確認與現有程式差異 |
| 5 | 這次工作的程式與測試 | 先 auth 或購物其中一條呼叫鏈，再讀必要依賴；不用一次掃全庫 |

程式入口：`MuscleCore分析資料/website/app/auth.py`、`app/store_v4.py`、`app/services/sku_gateway.py`、`app/templates/auth/`、`app/templates/store/cart_v4.html`、`tests/test_v4_routes.py`。這些路徑是相對 repo 根目錄；實際存在與內容由 AI 先核對。

**在 HEN 電腦上找不到文件怎麼辦？** 這次新進度表仍是 SAM 電腦的本機文件，不能假定已進 main；HEN 應取得檔案附件。HEN 交接與資料契約目前可從 SAM 的 `codex/sam-delivery-20261007` 分支取得作為閱讀來源；先核對該分支是否仍存在。不必為了讀文件，把 SAM 整個未合併分支合進 HEN 功能分支。文件不足時先做可驗證的程式盤點，列出缺哪份文件與提供人。

不要上傳 `.env`、Atlas URI、真實密碼、token 或私人帳號資料；文件與錯誤訊息先移除秘密。測試用可控本機／隔離資料；正式 Atlas 新帳號與 schema 變更交 SAM 處理。

## 三、提示詞要交代六件事

每次交代：**誰的工作、這次目標、讀哪些資料、哪些不能改、怎樣算通過、要交付什麼**。

不要只寫「幫我完成購物網站」。改寫成「我是 HEN，這次完成 R08 的 checkout 重送；沿用現有 v4 交易服務，驗同 checkout_id 同內容不重複扣庫存、不同內容依已定契約拒絕；交付 diff、測試結果與未驗範圍」。錯誤碼／欄位仍以本次核實契約為準。

## 四、可直接複製的指令

每個程式實作對話，先貼 A，再貼本次的 C 或 D。B 可以先在聊天 AI 分析；E 用來審查，F 用來發布，G 用來換對話。把 `<...>` 換成實際資料，不要照貼未填的欄位。

### B：先完成 R02 契約草稿

```text
請依剛才讀取的程式及文件，產出 HEN 的 R02 接口契約草稿。
先列現有接口，不自行新增 API 名稱或承諾不存在的功能。

每個接口寫清楚：方法／路徑或函式、呼叫者、身份／role／active 判定、
輸入、成功結果、錯誤結果、資料變更、重送規則、測試方式。
分成：註冊登入登出、停用／撤權、SKU 購物車、checkout、事件觸發。

特別查：舊 session 被複製後能否在登出或撤權後重播；
checkout 相同識別碼重送是否重複下單或扣庫存；
付款是 demo 還是真實服務；庫存／保留量／交易失敗由誰負責。
撤權機制依實際登入方式設計，不為了套模板新增 token 系統。

輸出「現有行為／建議行為／需要誰確認」對照表，未決事項明確標未決。
可先完成不依賴未決契約的文件與測試盤點；資料 schema 變更先交 SAM，
後台停用／付款取消語義與 JEFF 協調。
```

HEN 看完草稿後，把未決事項拿給主責確認；AI 產出的建議不能自行算成團隊已接受。

### C：會員與撤權，實際改程式

```text
現在實作 R08 會員／撤權這一段，依 R02 已確認契約：<貼上確認結果>。
若有未決項，先做不受其影響的工作，交付草稿並標出依賴。

在適合的乾淨工作目錄沿用 HEN 的 feature/auth-order 工作；
先讀取最新遠端 main／HEN 分支狀態，保留原目錄所有異動。
分支有分歧時先辨識並保留兩側提交；不得 force push 或用 reset 覆蓋。
不要把 SAM／JEFF 未合併分支的所有功能混進來。

沿用现有 auth 與 v4 users schema。補齊本次已確認的註冊／登入／登出、
active／role 即時驗證、停用／撤權後舊 session 的處理。
同時調整必要畫面／錯誤訊息、後端、測試與操作文件。

測試至少驗：重複 email、不合法輸入、錯誤密碼、未登入、停用會員、
customer 不能越權、已登入後降權／停用、登出／撤權後舊 cookie 重播，
以及適用於狀態變更請求的 CSRF。先根據實際契約判定預期結果。

用本機／隔離測試資料，不啟用既有 600 位合成客戶，不寫正式 Atlas，

請實際改檔並跑相關測試，最後提供修改檔案、行為變化、測試指令與結果、
瀏覽器是否已驗、SAM／JEFF 待交接口。這一步先保留本機成果，不發布。
若你不能操作檔案，請提供具檔名與上下文的 patch，標明「尚未套用／未執行」。
```

## 五、HEN 怎樣判斷 AI 是否真的完成

| AI 說法 | 要看到的證據 | HEN 應記錄的狀態 |
|---|---|---|
| 「我已讀文件」 | 實際檔名、章節、內容依據與讀不到的檔案 | 已讀／缺件 |
| 「已寫好」 | 實際 diff，或明確尚未套用的 patch | 本機修改完成／僅草稿 |
| 「測試通過」 | 執行指令、測試範圍、結果、exit code；跳過項另列 | 哪種測試通過，不能擴大成全站通過 |
| 「撤權成功」 | 舊 session 在約定條件下重播被拒絕 | 對應撤權案例通過 |
| 「checkout 冪等」 | 同 ID 重送筆數、庫存影響、不同 payload 拒絕結果 | 對應重送案例通過 |
| 「已推送」 | 遠端 SHA 與 PR URL 回讀 | GitHub 已交付 |
| 「CI 通過」 | 最終 head 的 CI 結果 | CI 通過；合併／部署仍另記 |
| 「整體完成」 | SAM 整合與遠端驗收證據 | 沒有證據就保留待驗 |

若 AI 只給計畫，可再下：「請在已授權範圍內實際修改檔案並執行測試；缺前置的部分列出負責人，繼續完成其餘可獨立工作。」若它說某文件不存在，先提供該文件，不要求它憑記憶補寫契約。
