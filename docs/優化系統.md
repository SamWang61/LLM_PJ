# 優化系統

本文件記錄 VibeCart 的操作優化與系統 Debug，供組員核對調整原因、實際行為及驗證結果。首項優化依 JEFF 與 SAM 意見，取消登出前的第二次確認，讓前台會員與後台管理員按一次「登出」即可結束目前裝置的登入。

English summary: Storefront and admin navigation now submit logout directly, with no confirmation page. CSRF validation and per-device session revocation remain in place.

## 優化紀錄

| 編號 | 日期（台灣時間） | 項目 | 原因與決定 |
| --- | --- | --- | --- |
| OPT-001 | 2026-10-21 | 移除登出二次確認 | JEFF 與 SAM 認為再次確認屬過度審核，改為按一次即登出。 |
| OPT-002 | 2026-10-21 | 重複按登入／登出不再出現 Bad Request | JEFF J1 實測與 #152 F01：登入其實已成功，畫面卻顯示 HTTP 400，必須修正。 |

## OPT-001 登出流程

| 操作 | 調整前 | 調整後 |
| --- | --- | --- |
| 商城導覽列按「登出」 | 開啟確認頁，再按「確認登出」 | 立即登出並返回商城首頁 |
| 後台帳號列按「登出」 | 同樣先進入確認頁 | 立即登出並返回商城首頁 |
| 完成提示 | 完成後顯示「您已安全登出。」 | 保留原有完成提示 |

前台與後台共用一份登出表單，使用原生 HTML 提交，不依賴 JavaScript，也沒有額外確認視窗。按鈕保留導覽列的外觀及鍵盤焦點樣式。

### Session 與請求處理

登出表單直接向 `POST /auth/logout` 提交同一登入 Session 的 CSRF token。缺少或錯誤的 token 仍回應 HTTP 400；移除的是畫面上的重複確認步驟。

v4 模式沿用目前裝置的伺服器 Session 撤銷與瀏覽器 Session 清除，因此舊 Cookie 不能重放登入；同帳號其他裝置維持登入。登出不更動購物車、訂單或帳號資料，也不執行全裝置登出。

原確認頁已移除，`GET /auth/logout` 現回應 HTTP 405，避免連結預覽或預先載入觸發登出。既有書籤或舊頁面須重新開啟商城，再使用新版「登出」按鈕。相關驗證工具改從商城導覽列的登出表單取得 token，須搭配本版部署使用；AI 洞察探針明確選取提問表單，避免誤選新增的導覽列表單。

### 驗證方式

自動測試從實際渲染的導覽列表單取得 token 並提交一次，核對商城會員、商城管理員及後台管理員均直接回到首頁，顯示完成提示，且不出現確認頁。另驗證錯誤 token 不會登出、舊 Cookie 失效，以及其他裝置仍可存取購物車。

GitHub 交付、CI 與正式站部署分開記錄；本項修正的推送不代表正式站已切換新版。

## OPT-002 重複送出登入／登出

**現象**：按下登入後，第一次請求已登入成功，但頁面顯示 Bad Request（HTTP 400）。回應較慢時再按一次或按 Enter 特別容易發生。

**原因**：登入與登出成功時會清空瀏覽器 Session（`session.clear()`），舊的 CSRF token 一起被清掉；第二次送出仍帶著舊 token，因此被 CSRF 檢查拒絕，瀏覽器最後顯示的是這次的錯誤頁。

| 情況 | 調整前 | 調整後 |
| --- | --- | --- |
| 登入成功後，同一表單又送出一次 | HTTP 400 | 直接導到第一次登入的目的地（管理員到後台、會員到首頁、有 `next` 且為站內路徑則回到該頁） |
| 登出成功後，同一表單又送出一次 | HTTP 400 | 回到首頁並顯示「您已安全登出。」 |
| 沒帶 token、token 錯誤，或不是剛才那次送出的 token | HTTP 400 | **仍為 HTTP 400**（不變） |
| 其他所有表單的 CSRF 檢查 | HTTP 400 | **不變** |

- **伺服器端**（`app/security.py`、`app/auth.py`）：登入／登出成功清空 Session 後，只記下「剛才送出所用 token」的 SHA-256 摘要（不存原 token）。之後該端點的 CSRF 檢查失敗時，只有在請求帶著**完全相同**的 token，且結果已經成立（登入時已是登入狀態、登出時已是登出狀態），才回應該結果；否則照舊 400。不會因此建立新的登入或撤銷其他 Session。
- **瀏覽器端**（`app/static/js/forms.js`，前台與後台都載入）：登入與登出表單送出一次後就不再重送，按鈕顯示「處理中…」；從上一頁返回時恢復可按。沒有 JavaScript 時由伺服器端處理。
- **驗證**：網站離線測試 323 passed／21 skipped，新增 `tests/test_auth_double_submit.py` 8 項（會員與管理員重複登入、站內與站外 `next`、重複登出、缺 token／猜 token／不同舊 token 仍 400、其他表單不受影響、密碼錯誤不會變成登入、只存 token 摘要、表單標記與腳本載入）；既有 REN 的 CSRF 測試未修改且通過。
- **相關**：回應偏慢（#152 F11／F04，約 2 秒）會讓重複點擊更常發生，效能改善另由 SAM 處理。
