## OPT-001 登出流程

| 操作 | 調整前 | 調整後 |
| --- | --- | --- |
| 商城導覽列按「登出」 | 開啟確認頁，再按「確認登出」 | 立即登出並返回商城首頁 |
| 後台帳號列按「登出」 | 同樣先進入確認頁 | 立即登出並返回商城首頁 |
| 完成提示 | 完成後顯示「您已安全登出。」 | 保留原有完成提示 |

前台與後台共用一份登出表單，使用原生 HTML 提交，不依賴 JavaScript，也沒有額外確認視窗。按鈕保留導覽列的外觀及鍵盤焦點樣式。

### Session 與請求處理

登出表單直接向 `POST /auth/logout` 提交同一登入 Session 的 CSRF token。缺少或錯誤的 token 仍回應 HTTP 400；移除的是畫面上的重複確認步驟。

v4 模式沿用目前裝置的伺服器 Session 撤銷與瀏覽器 Session 清除，因此舊 Cookie 不能重放登入；同帳號其他裝置維持登入。登出不更動購物車、訂單或帳號資料，也不執行全裝置登出。

原確認頁已移除，`GET /auth/logout` 現回應 HTTP 405，避免連結預覽或預先載入觸發登出。既有書籤或舊頁面須重新開啟商城，再使用新版「登出」按鈕。相關驗證工具改從商城導覽列的登出表單取得 token，須搭配本版部署使用；AI 洞察探針明確選取提問表單，避免誤選新增的導覽列表單。

## OPT-002 重複送出登入／登出

**現象**：按下登入後，第一次請求已登入成功，但頁面顯示 Bad Request（HTTP 400）。回應較慢時再按一次或按 Enter 特別容易發生。

**原因**：登入與登出成功時會清空瀏覽器 Session（`session.clear()`），舊的 CSRF token 一起被清掉；第二次送出仍帶著舊 token，因此被 CSRF 檢查拒絕，瀏覽器最後顯示的是這次的錯誤頁。

| 情況 | 調整前 | 調整後 |
| --- | --- | --- |
| 登入成功後，同一表單又送出一次 | HTTP 400 | 直接導到第一次登入的目的地（管理員到後台、會員到首頁、有 `next` 且為站內路徑則回到該頁） |
| 登出成功後，同一表單又送出一次 | HTTP 400 | 回到首頁並顯示「您已安全登出。」 |
| 沒帶 token、token 錯誤，或不是剛才那次送出的 token | HTTP 400 | **仍為 HTTP 400**（不變） |
| 其他所有表單的 CSRF 檢查 | HTTP 400 | **不變** |

- **伺服器端**（`app/security.py`、`app/auth.py`）：登入／登出成功清空 Session 後，只記下「剛才送出所用 token」的 SHA-256 摘要（不存原 token）。之後該端點的 CSRF 檢查失敗時，只有在請求帶著**完全相同**的 token，且結果已經成立，才處理為重送。登入另比對此次 Email 與密碼是否仍對應目前身分；不同帳號、密碼或另一角色的舊表單均回 400，取得新表單後才可切換身分。密碼只在請求記憶體內驗證，不另寫入 Session 或日誌；不建立重複登入或撤銷其他 Session。
- **瀏覽器端**（`app/static/js/forms.js`，前台與後台都載入）：登入與登出表單送出一次後就不再重送，按鈕顯示「處理中…」；從上一頁返回時恢復可按。沒有 JavaScript 時由伺服器端處理。
- **初版驗證快照**：原交付為網站離線測試 323 passed／21 skipped。後續本輪補入舊表單變更憑證的 P2 修正，最終整合驗證為 446 passed／0 skipped，包含真本機 MongoDB replica set；原數字不代表本輪測試結果。會員／管理員重複登入、站內與站外 `next`、重複登出、缺 token／猜 token／不同舊 token、不同帳號／密碼／角色、只存 token 摘要與表單單次提交均有案例覆蓋。
- **相關**：回應偏慢（#152 F11／F04，約 2 秒）會讓重複點擊更常發生，效能改善另由 SAM 處理。

## OPT-004 推薦曝光與結帳歸因
